# Сварщик (Welder)

Браузерная инкременталка: мастерская у реки, далёкое будущее Земли, раннесредневековый город с дуговой сваркой на меди, дереве и железе. Вертикальный срез примерно на 7 минут. Пиксельное 3D на three.js: сцена рендерится в 426×240 HDR и растягивается жёсткими пикселями, текстуры нарисованы как пиксель-арт, геометрия и текстуры стоят ровно. PS1-трюки (дрожание вершин, аффинные текстуры, дизеринг) есть в движке, но выключены флажками в `skin/default.ts`. Ни одного внешнего ассета: геометрия, текстуры и звук генерируются кодом.

## Запуск

```bash
cd welder
npm install
npm run dev            # http://localhost:5174   (?fresh — начать без сохранения, ?seed=N — другой сид)
npm run build          # проверка типов + сборка в dist/
npm run bot            # бот проходит срез по sim/ в Node и печатает время вех
npm run bot -- good -v # один профиль, каждая работа построчно
npm run bot -- --mirror  # проверка, что подмастерье варит как игрок
npm run probe -- bars  # один шов при разной скорости/длине дуги: металл, сплавление, прожоги, качество
```

В консоли браузера: `welder.game` (состояние), `welder.demo({ part: 'bars', speed: 1, arc: 2.5, wobble: 0.4 })` — сварить деталь скриптовой рукой и посмотреть рисунок шва (`speed` — доля идеальной скорости, `arc` — длина дуги в мм, `wobble` — дрожь руки в мм, `jerk` — рывки темпа).

## Управление

У верстака (свободный курсор, как в Dish Pit):
- ЛКМ — взять работу, купить, чиркнуть электродом и вести шов, после сварки бить шлак.
- Колесо мыши или W/S — длина дуги, колесо вниз приближает электрод.
- Пробел — маска.
- R — новый электрод.
- E — отойти от верстака.
- Мышь к самому краю экрана — повернуть голову.

По комнате (от первого лица):
- WASD — ходить, мышь — смотреть. Захват курсора по щелчку; если браузер его не даёт, смотреть можно, зажав ПКМ.
- E или ЛКМ — действие с тем, что в прицеле: встать к верстаку, взять работу, купить с полки, открыть заказы, отдать работу у двери.

Комната: на севере верстак, окно с колесом и стена с прибором и полкой. На западе окно на реку, полки с банками-аккумуляторами и угол подмастерья. На юге печь с чайником, ларь с углём, лежанка и щит с рубильниками. На востоке открытая дверь в снег с очередью, бочка, пруток и куртка на гвозде.

## Картинка

Одно место у верстака, как у раковины в Dish Pit. Работа лежит крупно по центру: каждая деталь масштабируется под ширину кадра, а сим по-прежнему считает в миллиметрах. Левая рука держит её клещами, правая с держаком или молотком тянется к курсору. Мышь к самому краю экрана поворачивает голову.

Стол заставлен вещами, которые сами служат интерфейсом:
- ящик со скрапом слева — работы ждут, щелчок берёт следующую;
- стопка сделанного справа — растёт с каждым заказом;
- горшок с монетами — сумма написана краской на боку;
- банка электродов с числом на ней;
- маска на расписном столбике со стрелкой: пробел опускает маску.

На стене:
- окно в снежную ночь: видны колесо и очередь, а заказчик стоит у самого окна;
- грифельная доска со счётом «сделано / ждут»;
- амперметр, стрелка и цифры которого идут за током реки;
- полка с покупками и бумажными бирками цен;
- рейка с инструментами.

Стиль — как на художественном референсе: серо-синий камень, тёмное дерево, ржавчина, тёплое пятно лампы на столе. Дуга даёт ореол, искры-штрихи и дизерированный дым.

## Структура

```
src/
  core/   rng.ts — mulberry32, отдельный поток на подсистему (orders, power, spatter, weld, world, apprentice)
          bus.ts — типизированная шина событий
  data/   types.ts · balance.ts (все числа баланса) · parts.ts · customers.ts · orders.ts · upgrades.ts · story.ts
  sim/    seam.ts — шов: ячейки по 2 мм (тепло, металл, пик тепла, шлак, отклонение, дыры, поры) + точки-чешуйки
          weld.ts — движок «верстака»: поджиг чирком, горячий перезапуск, длина дуги и её снос, залипание,
                    обрыв, перенос тепла и металла, прожог, брызги, сгорание электрода, отбивка шлака
          quality.ts — оценка шва → сорт → оплата; idealSpeed(толщина, ток)
          power.ts — река → колесо → динамо → банки → ток; мороз замедляет реку, провалы случайны
          apprentice.ts — Recorder пишет темп, смещение руки, длину дуги и паузы игрока; Replayer ведёт ими второй верстак
          game.ts — фикс-шаг 1/60, команды, маска и засветка, часы, сюжетные вехи, доска, подмастерье, финал
          guide.ts — что подсветить следующим и какую короткую подсказку показать
          stats.ts — апгрейды → параметры; условия и «почему нельзя»
          save.ts — версия, только идентификаторы и числа
  view/   renderer.ts — сцена → HDR 426×240 → пост: маска, засветка, послеобраз, ACES, 15-бит цвет с дизерингом
          ps1.ts · textures.ts · workshop.ts · partMesh.ts · bead.ts · particles.ts · tools.ts · camera.ts · ui.ts · view.ts
  audio/  audio.ts — синтез: шипение дуги («жарящееся сало»), треск длинной, гудение короткой, сбои тока,
          динамо (высота от колеса), вода и лопасти, ветер, вой с эхом от стены, удары, монеты
  skin/   default.ts — палитра, свет, параметры поста, флажки ретро-эффектов (по умолчанию выключены); sim/ его не видит
  i18n/   en.ts · ru.ts — тексты, по умолчанию английский
  main.ts — старт по клику, аккумулятор времени по performance.now, сохранение в localStorage
  dev.ts  — демо-сварка для консоли
bot/      bot.ts (прохождение), probe.ts (один шов)
```

`sim/` не трогает DOM, three.js и звук и не вызывает `Math.random`: случайность идёт только через именованные потоки. View и звук читают состояние каждый кадр (дуга, тепло шва, ток) и слушают события (`arcStrike`, `slagChip`, `revealed`, `handedOver`, `bought`, `howl`…). DOM-интерфейс меняет содержимое только по событиям, а каждый кадр лишь двигает подсказку и курсор.

Новая деталь — это запись в `data/parts.ts`: швы-полилинии в мм и `shape` с параметрами для одного из построителей в `view/partMesh.ts`. Новый заказ — запись в `data/orders.ts`, новый апгрейд — запись в `data/upgrades.ts` с эффектами `set/add/mul` над параметрами из `sim/stats.ts` и условиями `requires`. Код при этом менять не нужно.

## Как устроен шов

Шов в sim — одномерное поле ячеек вдоль стыка и список точек-чешуек. Каждую точку дуга оставляет раз в такт (0,085 с), и у неё есть позиция, смещение руки, ширина, высота, скорость, длина дуги, тепло, ток и флаги (поры, холодный, перегрев, длинная или короткая дуга).

- **Тепло** приходит гауссом вокруг дуги, остывает экспоненциально и растекается вдоль шва. Выше порога детали получается прожог. Это же поле даёт свечение валика: белый, жёлтый, вишнёвый, тёмный.
- **Металл** откладывается независимо от скорости, поэтому медленно — горка, быстро — тонко и с недоливом.
- **Сплавление** — пик тепла под присадкой: слишком быстро или слишком длинная дуга дают холодный непровар.
- **Длинная дуга** даёт брызги, поры и рассеянное тепло. **Короткая** — меньше тепла и залипание. **Слабый ток** — сбои дуги (горячая ванна перезажигается сама) и холодные места.

View строит валик из точек инстансами: полуэллипсоиды со светлым передним краем и тёмным задним, внахлёст. Ровный темп даёт ровную «рыбью чешую», рывки — комки и волну, медленный проход — толстый валик, длинная дуга — поры и брызги вокруг. Пока шлак не отбит, видна только корка.

Подмастерье — второй верстак того же движка. Он повторяет записанный темп, дрожь руки, длину дуги и паузы игрока на простых работах, поэтому его качество складывается само, по той же физике. Проверка (`npm run bot -- --mirror`):

| рука игрока | игрок, простые работы | подмастерье |
| --- | --- | --- |
| хорошая | 0.87 | 0.74 |
| средняя | 0.72 | 0.54 |
| плохая | 0.32 | 0.28 |

## Темп (бот, сид 1)

Три профиля руки отличаются темпом, дрожью, удержанием дуги и «временем на подумать».

```
milestone             good  average     poor
firstStrike           0:02     0:03     0:05
firstCoin             0:11     0:13     0:19
shelf                 0:30     0:33     0:45
buy:coated            0:31     0:36     1:19
buy:glass             0:54     1:57     2:22
buy:jar               1:19     1:30     3:47
board                 1:42     1:54     2:19
buy:apprentice        2:49     4:30        —
apprenticeFirst       3:08     4:49        —
buy:cable             2:04     3:06        —
buy:wheel2            3:49     6:07        —
finaleStart           5:00     5:55     5:55
finaleEnd             6:07     7:06     8:31
```

Бот реагирует быстрее человека, особенно в первые минуты. По моей оценке (с живым игроком не проверялось), доска у человека откроется ближе к 2:30–3:00. Финал начинается, когда куплено второе колесо и прошло 5:00, или в 5:55 без всяких условий. Поэтому смена заканчивается примерно на 6–8-й минуте при любом темпе.

## Решения и отступления от брифа

- **Доска заказов — сюжетная веха** (после 5 заказов), а не покупка. Подмастерье и второе колесо требуют доску, и эта причина видна в подсказке на полке.
- **Сдать деталь** можно щелчком по детали за столом или по заказчику в двери. Решётку в финале уносят сами.
- **Шлак отбивается кусками**, длина куска зависит от качества шва: на хорошем шве корка отходит длинными пластами.
- **Длина дуги сама растёт** (электрод сгорает, 0,25 мм/с при номинальном токе), поэтому её приходится подправлять колесом. Это заметно на слух: ровное шипение переходит в треск.
- **Маска** — не затемняющий оверлей, а экспозиция HDR-кадра через стекло: в маске видно только то, что освещено дугой или светится само. Засветка без маски уходит за ~0,3 с, послеобраз держится ~2,4 с и остаётся на месте экрана, где была дуга.
- **Текст интерфейса — DOM поверх канваса** моноширинным системным шрифтом: внешних шрифтов нет.
- **Сохраняется всё, кроме валика в работе.** Незаконченный заказ после загрузки возвращается на кучу или на доску.

## Что проверено, а что нет

- `npm run build` проходит без ошибок типов. Бот проходит срез тремя профилями. Тест подмастерья — таблица выше.
- В headless Chromium (программный рендер SwiftShader) скриптом пройдены: старт, взятие работы, поджиг, сварка в маске и без, отбивка, оценка, оплата, полка с причинами, доска, подмастерье, ночь, решётка, конечная карточка, русский язык, сохранение и продолжение.
- Нагрузка в самый насыщенный момент (дуга с тенями, искры, подмастерье) — около 100–240 вызовов отрисовки и ~3,5 тыс. треугольников. Кадр на CPU около 1,2 мс, шаг симуляции 6 мкс. **На реальной видеокарте 60 кадров не замерялись**: на машине разработки нет GPU.
- **Звук на слух не проверялся** (нет аудиовыхода). Проверено только, что синтез поднимается и не даёт ошибок.
